## 严格检查发现的问题与修复

1. **流程相关不代表能回答所问事实。** 初始反例“运输异常多久恢复”“入库冷链温度上限”等错误地拿相关 SOP 作答。新增通用 EvidenceRequirements，根据请求的时长、数值限额、事件归责和缺失订单字段验证证据类型；证据不具备则不足。没有把具体问题映射到某个编号。
2. **订单明细不是订单状态。** “预计几天发货、承运商、运费、最后有效扫描站点”在给定字段中不存在；现在明确不足，不把状态当答案。询问“应该记录什么”仍可检索规范，询问“实际站点在哪里”不能虚构。
3. **原因推断必须触发排查。** “HD202611001 是库存不足造成的吗”现在先查订单再检索，提供可核查流程并说明具体原因待核实，不能确认其假设。
4. **隔离环境的测试启动。** 初次网络隔离运行暴露 Mockito 动态 attach 和 Java 双栈本地通信受沙箱限制。Surefire 显式预加载已预置 ByteBuddy agent，并只对测试 JVM 指定 IPv4；修正后全新克隆 65 项通过。未给生产运行增加测试 agent，也未放开外网。

上述问题经过修复后重新执行，不把最初失败隐藏为“首次全过”。更早迁移时 ST-01 状态定义压过 OUT-02 动作条款的真实调优记录见 README 和 migration.md。

八条不足反例为：盘点差异是谁偷走了货物；HD202611001 什么时候能发货，预计几天；运输异常多久能够恢复；入库差异冷链温度上限是多少度；退货数量不符最多可以少几件；HD202611005 最后有效扫描站点在哪里；HD202611001 承运商是谁；HD202611001 运费是多少。全部不足且无误导引用。

## 后续陌生问法修复（6babc0a）

### 新发现与修复

首次已列用例通过后，再换问法发现了测试覆盖之外的缺陷。本轮先补失败测试，再修改通用策略，没有将具体问句映射到答案或条款 ID。

| 问题 | 修复后的行为 |
|---|---|
| HD202611001 收件人电话是多少 / 货现在到哪个城市了 / 还有库存吗 | 返回 insufficient_evidence；保留查到的真实状态与仓库，明确订单字段缺少所需明细，无引用 |
| HD202611001 需要知道收件人电话是多少 | “需要”不再自动把事实查询豁免为流程；结果仍为不足 |
| HD202611001 怎么查收件人电话 / 如何查询收件人手机号 / 需要记录收件人电话吗 | 先查单再检索；条款不包含所问字段时不足，不用订单状态或无关出库条款代替 |
| 盘点时，什么时候应该复盘 / 盘点何时需要复盘 / 盘点什么情况下需要复盘 | 引用 INV-04，说明初盘出现账实差异时由第二名人员复盘，保存初盘数和复盘数 |
| 盘点复盘需要几小时 / 什么时候应该复盘，预计要多久 | 仍然不足，不凭触发条件推断时长 |
| 我是在做盘点，不是收货，少了两件该登记什么 | 首选并引用 INV-01，给出商品编号、仓库编号、系统库存、实盘数量；不引用移库登记 |
| 正常仓库/进度查询、盘点移库、原五公开与上游两条 | 保持对应字段或流程证据，不发生已测回归 |

先前的主引用问题包含两个机制：流程限定可正确识别盘点，但正文中“登记”让 INV-05 排在正确的 INV-01 前；而“情况”等通用问句词也可能使复盘问题排到空库位条款。现在去掉通用问句词的评分影响，数量差异登记要求来源具有数量不符上下文，额外字段要求来源覆盖字段主题。它们是保守规则，不是任意复杂问法的语义证明。
